## Phase 4 实施方向

`next` 按 P4-0 → P4-1 → P4-3 → P4-2 → P4-4 → P4-5 → P4-Gate 交付。现有单节点 DSH 用于主线业务验收。双 Windows 通过 Tailscale 执行独立工单的能力由 `feat/multi-node` 并行交付。

控制面持有 Project、Ticket、Assignment、会话索引、权限和审计。节点是 Superagent 实现的程序，负责本机工作区、调用后端适配器和回传执行事实。Agent Session 由执行后端创建、持有和运行。DSH 保留插件作为适配入口，其他后端通过各自的适配器接入。Router 所在节点为主节点，首次配置固定 Router 后端实例。重启核对原绑定，配置冲突显式报错。首版暂缓提供 Router 后端更换功能。

| 分支 | 实施边界 |
| --- | --- |
| `next` | 定义业务目标、权限与生命周期校验。接收通过归属校验的报告，按原 Ticket 更新状态并通知合法上级。实现摘要、审批拒绝上报、订阅直唤醒及对应的持久投递。 |
| 跨设备功能分支 | 实现节点连接、能力声明、后端适配、本机工作区解析、Assignment 与实际节点及后端的绑定、命令回执和节点回报补交。完成双机真机验收后，再与当时的 `next` 集成。 |

两条线共用 [`src/control/node-resolver.ts`](../../src/control/node-resolver.ts) 的签名。主线从单 DSH 节点解析实际目标，跨设备线负责节点注册表和适配器。节点补交沿用原报告 ID，控制面去重、落库后确认接收，再按业务归属通知用户或上级。双方使用各自的模块、SQLite 表和协议文件尾部区块。双节点首版覆盖独立工单。Android、跨节点项目文件同步和故障自动改派另行设计。

### P4-0 先评审节点解析与投递契约

[P4-0 评审稿](../022-phase4-coordination-architecture.zh-CN.md)记录四类通信机制、五条路径的四时点核验、失败与回执口径，以及外部事件默认直达和仅操作员手动显式开启双层路由的规则。P4-0 交付共享类型与设计，P4-1 接入运行时。

当前 `ControlPlane` 已持有单一 `nodeId`、`NodePort`、Session 确认代际与现有停止/撤权检查。Session 消息、派工、定时交付和回执仍各有校验与调用路径。P4-0 先核对旧插件 Source / Trigger / Thread Subscription、独立控制面的 Session event / Report / Scheduler，以及 Router 的自动交接与手动 Relay Proposal。复用已有领域关系，保持旧插件与独立运行时的数据边界。Thread 的 Ticket 关联、下级会话摘要订阅和外部事件订阅各自保留生命周期。

持久化业务目标、当前操作所需的派工或会话身份、来源和授权范围。首次发送、重试、恢复以及等待 ensure 返回后，重新读取权威状态，核对当前权限、归属、停用/撤权和代际。统一解析入口从绑定记录取得 `nodeId`、后端实例 ID 和会话引用。既有单节点记录通过兼容规则识别原绑定，新建远端 Assignment 在首次发送之前保存执行目标。定时任务依然要求 PM 预先启动，显式恢复才可解除人工停止。已有目标缺失、离线或身份不符时保留原目标并给出原因，不回落到主节点或接替的 Assignment。

设计评审明确区分控制面对节点的信任代际、会话/派工的生命周期、工具令牌版本。普通令牌刷新仍按既有规则。对现有回传无法可靠归因的路径，先说明协议兼容方案和证据边界。保护授权失败、目标失效、节点离线、节点明确拒绝、发送结果未确认的独立口径；一次节点接收回执与回合实际启动、工单完成分别记录。节点离线和普通工具错误不计入审批拒绝。

### 按依赖交付

1. **P4-0 先评审两条线共用的契约。** 交付路径清单、业务目标与执行绑定、回执与报告身份、状态及重试矩阵、旧数据兼容和回滚边界。P3 已授权的常规分派继续免逐次确认。涉及跨域访问或新增授权时单独评审。
2. **P4-1 先落实共享解析与报告闭环。** 先接 Worker→PM/Router 和 PM→Router 的投递，再按矩阵让会话和派工命令复用。即时报告和周期报告分别验证；把报告去重、可查失败和最小恢复能力随第一条链路交付，P4-5 再验证各路径的一致恢复行为。
3. **P4-3 优先验证真实拒绝，随后完成 P4-2/P4-4。** 审查事件从实际权限守卫采集，按合法上级去重唤醒，原拒绝保持有效。P4-2 按明确授权从直属下级会话生成零 LLM 增量摘要。P4-4 用合成事件验证默认直达发起者或指定目标、操作员手动显式启用的双层路由，以及失效、限流和去重。
4. **P4-5 收口持久投递与恢复。** 逐条确定授权寿命和消息寿命。可确认未发出的命令，且目标、代际和授权仍有效时，按原幂等键重试。已尝试但缺回执的命令先查接收证据；缺少跨重启去重或核对证据时保留未确认。人工 Relay 仍遵守确认和失效规则。业务事件日志继续承担审计与查询，待投递记录有独立保留和清理边界。

### P4-Gate 增补验收

在 `next` 上验证派工、会话干预、报告通知、事件直唤醒、重试和重启恢复经过统一解析。覆盖目标消失、旧派工和旧回合、会话或节点代际变化、撤权、节点离线及回执丢失，核对实际执行调用、回执和业务状态。用真实后端演示两 Worker 报告、只订阅其中一个、权限拒绝触发上级审查，以及合成事件直达预定目标。使用现有 DSH 部署回归旧插件、Scheduler 和 P3 自动交接。`next` 的 P4-Gate 通过后可进入 Phase 5。

跨设备分支合入前，在两台 Windows 上各用一个真实后端（可以相同）通过 Tailscale 并行执行独立工单，验收各自写入本机工作区、定向干预、断链后原节点补交回报以及 Router 固定绑定。另用能力不同的模拟适配器验证跨后端路由和回传归属。双机通过后，在集成版本复跑双机用例、P3-Gate 与届时 `next` 已落地的协作和记忆回归。以同一集成构建的结果决定合入。

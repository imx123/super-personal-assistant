2026-11-17。调查以 `next` 的 `3dfbf4a` 为基线。当前项目内的 PM 与 Worker 共用项目工作区。独立 Ticket 使用自己的目录。控制面按项目分配路径，节点的 `review.diff` 只带 `projectId`，PM 看到的是目录快照。差异涵盖该目录内多人的改动，现有 API 无法可靠归因到单个 Assignment。

只读审阅要求工作区是独立仓库，并限制 Git 元数据及可运行程序的配置。linked worktree 的 `.git` 指向外部仓库，现有校验会拒绝。依赖外部对象库的借用式克隆也会被拒绝。保留这些约束，是评估生产方案的前提。 [工作区推导](../../src/control/control-plane.ts) · [节点命令](../../src/node/dsh-port.ts) · [审阅校验](../../src/node/review-diff.ts)

## 可复现实验

在仓库根目录运行以下命令。脚本为每次实验创建一个新目录，使用合成文件、本地 Git 和临时身份，保留结果供检查。 [实验脚本](workspace-spike.ps1)

```powershell
pwsh -NoProfile -File docs/roadmap/workspace-spike.ps1
```

默认将 `checks.md`、`evidence.json` 和 Git 输出写到 `.artifacts/phase3-workspace/` 下。验证环境为 Windows、PowerShell 7 和 Git `2.55.0.windows.3`。Windows 沙箱曾拒绝本地 clone 的 Git 子进程，实测改在获准的隔离环境中执行。19 项检查全过，本机证据目录为 `spike-20261117-181345-f41104`。

| 用例 | 实测结果 |
| --- | --- |
| 共用目录，两个 Worker 写不同文件 | 快照同时包含两人的改动，没有可验证的 Assignment 归属 |
| 共用目录，写同一文件 | 后一次写入覆盖前一次，快照只显示留下的版本 |
| 两个 linked worktree 写不同文件 | 各自提交可独立取差异，合并通过 |
| 两个 linked worktree 写同一文件 | 合并返回冲突，文件保留两边修改和冲突标记 |
| 一个 Worktree 留下未提交文件 | 项目与旁边 Worktree 的状态和差异哈希均保持原样；Git 拒绝移除有未提交改动的目录，现场保留 |
| 审阅限制对照 | 拥有独立 `.git` 和对象库的本地克隆通过脚本中的规则对照；linked worktree、借用对象库及指定外部 diff 程序的克隆被拒绝 |

这是 Git 层实验。最后一项在脚本中复现了相关校验条件，未在真实 DSH 上切换工作区或更换 PM 的差异读取路径。

## 候选方案

| 方案 | 归因与并行 | DSH 和审阅接口 | 冲突、清理及回滚 |
| --- | --- | --- | --- |
| 每 Assignment 一个 linked worktree | 有独立目录和分支，共用对象库及部分仓库配置 | 需将 Assignment 和工作区绑定；现有审阅拒绝该 Git 布局，后续调整必须重新核验路径和 Git 元数据边界 | 可以只清理相应派工；未提交改动保留，合并冲突单独处理 |
| 每 Assignment 一个独立本地工作区 | 各有工作目录和对象库，按固定起点取差异 | 新工作区可使用当前独立仓库的校验条件。协议仍需传项目、Assignment 及允许的路径并校验归属 | 隔离更直接，承担磁盘、初始化和成果汇总成本；可保留失败目录 |
| 共用目录，按派工保存补丁或阶段快照 | 串行写入时能按快照切分；并行写入仍可能互相覆盖 | 路径保持现状。要提供可靠归因，必须约束写入范围或让派工分时写入 | 补丁可检视和重放，冲突需要单独处理。不能用快照推断未留证据的作者 |

## 当前取舍

控制台已在项目工作区旁提示同一文件的并行改动可能互相覆盖。生产继续沿用当前共享路径及审阅校验。

若后续要启用生产隔离，建议先在专用 DSH profile 核验每个 Assignment 的路径绑定、PM 的只读差异和故障恢复。独立仓库是优先验证的候选，因为它可以沿用现有 Git 边界；linked worktree 需另外审查对外部 Git 元数据的访问设计。切换前由用户选择保留共享目录还是启用隔离，失败目录如何保留、分支由谁合并也在该次决策里确认。

在真实 DSH 候选验证完成前，共享目录的并行写入和 PM 快照归因仍有限。

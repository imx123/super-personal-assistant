# 019 快路由

P3-2 在 Router 的消息队列内处理目标和动作都明确的请求。命中规则时，控制面直接完成状态查询、派独立工单、续接工单或向现有项目 PM 交接。其余请求由现有 Router 模型处理。

## 在控制台使用

| 输入示例 | 结果 |
| --- | --- |
| 创建一个隔离的示例文件 hello.txt，写入 hello。 | 创建独立工单，节点启动 Worker，Worker 的报告回到原工单 |
| 继续工单 `<完整工单 ID>`，补充一项验收说明。 | 在 Router 拥有且仍开放的工单上追加指令 |
| 告诉项目「周报整理」生成本周摘要。 | 唯一项目名匹配时交给该项目已有的 PM |
| 查询工单 `<完整工单 ID>` 的状态。 | 直接显示当前工单记录 |

工单按完整 ID 匹配。项目按完整 ID 或引号内的完整名称匹配。目标有歧义、缺少交办动作或需要新增授权时，规则层记录升级原因，由模型进一步处理。带附件的消息沿用原对话入口。快路由使用确定性规则，OpenSquilla 和小模型接入是后续可选项。

提交后，首页「快路由直接处理的消息」显示项目、工单或会话及当前处理结果。Worker 尚在启动时显示待处理。确认信号来自节点回执和领域派工状态，工单回报仍由 Worker 自己提交。

## 顺序与送达

普通对话与快路由请求共用 FIFO 队列。Router 回合进行中，后续提交排队。停止或撤销 Router 权限会拒绝新的请求，已排队的请求保留在本地。快路由动作执行前重新核对工单、项目和会话。项目必须 active 且 PM 会话可用。向 PM 交接仅携带这条请求的正文；工具执行仍受项目 Mandate 与原有权限规则约束。

| 回执状态 | 含义 |
| --- | --- |
| `accepted` | 等待队列处理 |
| `routing` | 控制面正在执行 |
| `queued` | 已记录任务或输入，等待目标 |
| `assigned` | 目标确认接收，或状态查询已完成 |
| `escalated` | 由高层 Router 处理 |
| `failed` | 执行失败，回执附原因 |
| `unconfirmed` | 无法确认动作结果，回执保留原请求 |

`router_queue` 与 `fast_route` 在控制面的控制台数据库内。接受请求及领取快路由动作时，两张表的状态成对写入。同一请求 ID 的重复提交在记录保留期间返回已有结果，正文、附件或模型不同则返回 409。投递拒绝或缺回执时，控制面记录结果并推进下一条。重启时，执行中的动作记为未确认，避免重复创建或投递。

独立工单的创建、Worker 启动及现有工单续接沿用 Engine 和 NodeExecutor。快路由不涉及自动创建 Project。旧 Router 转发提议仍可确认，常规高层自动交接和四条件建项目规则由 P3-3 处理。

控制面自动化覆盖精确目标、歧义、顺序、权限、失败与重启。环境、命令及真实模型证据见 `docs/roadmap/PHASE3_5_EXECUTION_LOG.md`。

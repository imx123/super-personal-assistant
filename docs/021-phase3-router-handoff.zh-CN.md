# 021 高层 Router 的自动交接

P3-3B。在首页用自然语言提出属于已存在项目的任务，不需要说「转告 PM」，也不需要点确认：高层模型选出正确的项目后，控制面自己把工作交给那个项目的 PM，并把真实的接收和对象显示出来。

## 谁在什么时候动手

| 步骤 | 谁做 | 说明 |
| --- | --- | --- |
| 读消息 | 快路由 | 目标、动作都明确的消息仍然由规则直接处理（P3-2）；「请在「周报整理」补充本周数据」这类自然指令没有交办动词，规则不猜，升级给高层 |
| 选目标 | 高层 Router | 模型读 `control_router_summary`，判断这条请求属于哪个已有项目，调用 `control_router_pm_handoff` |
| 判断 | 控制面 | 服务端复核：请求确实要求动手、目标唯一且确实是本人点名的项目（或本请求自己建的项目）、交给 PM 的内容逐字来自本人原话、范围不越界 |
| 投递 | 控制面 | 消息直接送到目标项目的 PM 会话，不需要人工确认；PM 自己决定建几张工单、怎么派工 |
| 展示 | 首页 | 显示项目、PM 会话 ID、真实状态（已确认 / 待送达 / 未确认 / 失败 / 未投递）和原因 |

已验收的快路由继续处理明确的「告诉项目「……」」。B 真正验证的是自然指令走模型决策，而不是再加一层简单强制的快规则。

## 服务端复核的四件事

模型能决定的只有两件事：**哪个项目**、**说什么**。其余都由控制面按本人原话复核（`src/control/router-handoff.ts`）。

| 复核 | 依据 | 不成立时的原因码 |
| --- | --- | --- |
| 工作意图 | 请求本身要动手 | `no_work_instruction`、`discussion_only`、`request_question`、`request_negated` |
| 唯一目标 | 请求点名了恰好一个项目（完整标题或 ID）；请求自己建的项目按创建绑定 | `target_not_named`、`ambiguous_target`、`target_mismatch`、`created_project_mismatch`、`unknown_project` |
| 原话边界 | 交给 PM 的内容是本次请求中的一段连续原文 | `instruction_not_in_request`、`cross_project` |
| 范围 | 不越到别的项目、不要新授权、不可逆范围不自动做 | `cross_project`、`new_authority`、`irreversible_scope` |

补充规则：

- 目标解析用权威项目记录，同一处文字匹配多个标题时取较长者。「周报整理」匹配一个项目，分别点名「周报整理」和「周报」则有两个候选。
- 「补充」「追加」「跟进」这类词和「改」一样算要求动手。
- 歧义、多候选、越权、敏感跨域、高风险不可逆、需要新增授权的请求都退回复核或走已有授权限制，控制面不采信模型自称「授权已通过」。
- 交付内容只允许包含本人原话片段，历史对话、附件内容、其他项目私有材料都进不了 PM 的收件箱。

## 幂等、状态与一次一件事

- 一条请求最多一个主要路由结果：派了独立工单、做了管理动作、提了待确认提议，就不再交给 PM；反过来也一样。
- 同请求已选的项目门禁和 PM 投递不串线：请求自己建的项目只能收到自己的工作。
- 复用稳定投递键（`router-handoff:<requestId>`、`router-brief:<requestId>`），节点侧最多执行一次。
- 控制面持久记录已接受的高层动作（`router_handoff` 表，请求 ID 唯一）。重复调用、并发调用、重启后的调用返回既有回执或未确认，不加发，也不凭旧记录恢复已失效的授权。
- 被判定拒绝的交接可以换一个成立的判定重来：拒绝没有送出任何东西。已经送出过的（成功、失败或未确认）不再重发。
- 目标已暂停或结束、PM 被停或撤权、节点拒收，都给出准确状态，不隐式复活。

## 门禁建项目后的工作说明

高层四条件门禁放行并创建项目、启动真实 PM 后，同一请求只为这个新项目发送一次工作说明：

- 工作说明使用通过门禁的那条完整请求，保留各模块和工作限制。控制面复查范围后，只发给新项目的 PM。
- Router 不为这个项目建工单，也不改别的项目；PM 收到工作说明后自行建单、派工。
- 本人明确「仅创建 / 待命」时保留创建后空闲语义：不发送工作说明，PM 保持空闲，记录写明原因。

## 兼容

- 旧的 `control_router_pm_proposal` API 与「显式提议 + 人工确认」能力保留不变，普通授权任务走新的自动交接，不走提议。
- P3-2 现有快层行为、手动明确建项目、P3-1A 停止语义与既有 SLA 都不改动。

## 页面

首页新增「高层 Router 交给项目 PM 的工作」一栏，沿用快路由与门禁的记录样式，显示：本人原话、项目、PM 会话 ID 与实时状态、实际送达的内容、模型给出的短依据，以及排队 / 未确认 / 失败的原因。

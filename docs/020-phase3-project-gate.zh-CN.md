# 020 高层 Router 与自动创建项目

P3-3A 继续使用现有 `router.v1` 会话运行模型。快路由处理它能确定的动作，其余请求进同一消息队列并交给高层 Router。首页分别显示快路由、模型处理和升级原因。

## 自动创建项目

高层 Router 调用 `control_router_project_gate` 时，控制面核对四个条件。

| 条件 | 要说明的事实 |
| --- | --- |
| `multiple_independent_modules` | 至少两个模块，各自负责一块明确工作 |
| `reasonable_decoupling` | 各模块能分开交付，共用接口和依赖明确 |
| `genuine_parallelism` | 各模块有实际的并行推进条件 |
| `benefit_outweighs_coordination` | 并行收益可以抵消对齐、集成和管理成本 |

每个条件提交判断和理由。工具提交 `requestAnchor` 与各模块的 `anchor`，控制面对照本次用户原话核验引用和工作范围。用户只要求讨论、条件不齐或理由仅诉诸复杂、耗时，控制面拒绝自动建项目。请求点名已有项目或拟建标题与已有项目完全一致时，返回已有项目线索。引用和范围校验使用确定性规则，模型判断质量仍需通过实际样例评估。

用户明确要求创建项目时，可继续走项目页，或经 Router 调用 `control_router_create_project`。Router 的显式工具由控制面根据用户原话确认用户是否要求创建。模型不能自行声明用户已经同意。

## 幂等与回执

自动与显式创建共用同一请求的领域项目标识。控制面持久记录四项判断、模块、项目 ID 和 PM 会话。当同一请求已创建项目时，重复调用和控制面重启返回原回执，不重新建项目或唤醒 PM。进程如果在创建中断开，控制面从领域数据核对原项目，无法确认时返回未确认结果。

首页「自动建项目的判定」显示证据及决策。项目创建与 PM 就绪分别显示，PM 启动失败时项目仍存在。项目工单及 Worker 由 PM 管理。对已有项目的常规高层自动交接属于 P3-3B。

## 验收

`tests/control-plane-project-gate.spec.ts` 覆盖四项条件、用户原话、既有项目、并发、重放和角色边界。测试、模型环境与本机证据见 `docs/roadmap/PHASE3_5_EXECUTION_LOG.md`。
